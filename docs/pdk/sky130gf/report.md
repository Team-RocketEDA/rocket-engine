## Decision (ticket asked for this first)

DUAL-SCOPED registration — the pip package is layout-cells
convenience, the open_pdks tree stays the decks authority:

- `sky130A` (tree, pdk-sky130A catalogue entry): drc, lvs,
  extract, sim. Full decks, already proven (DRC-SKY130,
  EXTRACT-SKY130, SIM-SKY130 slices). Unchanged by this lane.
- `sky130gf` (pip, `sky130==1.0.0`): layout, cells,
  klayout-tech ONLY. The pip profile declares drc/lvs/extract/
  sim n/a with a pointer to the tree deck, and runs pin the
  distribution in the ingredient closure — capabilities never
  overlap, so one process never registers two confusing ways
  and no run can silently mix distributions.
- volare REJECTED as a lane distribution: it fetches the same
  open_pdks tree content (not a distinct distribution), needs
  GitHub network + token at provision time, and would add a
  third confusing sky130 path.
