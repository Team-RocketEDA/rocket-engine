# ADR-014: Contract-first editor, component and tool API

*Status: accepted design, 2026-11-01; provider migration pending. Supersedes ADR-003 authority for v1; refines ADR-008/011/013.*

## Context

The product owner requires a KiCad-style schematic/symbol/cell/layout editor combining Xschem's circuit workflows and Magic's technology-driven physical authoring, with full library scripting and all selected EDA tools. Clients must share one engine process. The existing endpoint catalog is large and implementation-derived; opaque job dictionaries and prose descriptions cannot coordinate a wave of parallel agent refactors without payload drift.

The owner requested the ECC API Design, AI-First Engineering and Contract-First skills, a small public vocabulary, explicit tool modes, general catalog discovery, source-authoring component presets, a renamed canvas TOML file and scoped editable testbench templates. Three independent reviews covered editor identity, execution/admission and upstream toolchain/model behavior. Findings and external sources are in [API-V1](../work/API-V1/).

## Decision

1. **One canonical versioned boundary contract.** [contracts/engine-v1.schema.json](../../contracts/engine-v1.schema.json) is the entry to the authoritative v1 schema/catalog/example bundle. The schema defines requests/results/errors/events, editor entities, canvas config and closed task options. Consumer types, help, examples and expanded schemas derive from it. Docstrings explain code and conform to the artifact. ADR-003's current generator remains authoritative for existing v0 behavior until migration; generated v0 files are not rewritten by hand.
2. **Six transport-neutral methods:** `describe`, `query`, `edit`, `run`, `script`, `watch`. Task/analysis selectors carry domain vocabulary; no endpoint per simulator command or Python method. HTTP/MCP/stdio wrappers use the same shapes/semantics and same runtime. Read-only help comes from the registry without constructing another Engine or executing project imports.
3. **Button workflows and individual tools share `run`.** Named workflows expand coverage plans into gated child tasks; required unsupported/skipped checks block a verified claim. Registered standalone call points include all analyses/stages in the contract catalog. Libraries/subordinate solvers remain discoverable dependencies. Qualification and target readiness are explicit; an enum is not support evidence.
4. **Circuit component presets:** `spice_block`, `gdsf_component`, `hdl_component` expand one common component identity, source/view records, canonical ports and symbols/cells as appropriate. A component's source language does not replace its identity. `assembly`/`primitive` support hierarchy/PDK cells. PDKs, IP catalogs, packages and project hierarchy are all query sources. Future `src/ip/<language>` layout is an internal packaging decision.
5. **Standard honest SPICE slot.** Every circuit component has `models.spice` with provided/derivable/unavailable/not_applicable state, provenance, dialect, port order and dependencies. PDK device models and standard-cell subcircuits are separate assets from Liberty/LEF/GDS. Missing SPICE blocks relevant simulation rather than editing. Optical/abstract/unmapped RTL models are never invented. Annotation and testbench harness entities are distinct from manufactured circuit participants.
6. **`canvas.toml` replaces `canvas.cst`.** It owns design intent, registered inline tool knobs or contained config references, PDK/technology references and one selected authored HDL (`verilog`, `systemverilog`, `vhdl`, or qualified `amaranth`). Generated downstream Verilog is not a second authored language. Amaranth requires added/pinned/qualified tooling; Hardcaml remains future. Explicit migration creates a new revision; reject conflicting active files and preserve old run snapshots unchanged.
7. **Editors use atomic typed changes and per-entity CAS.** Preserve ADR-008. The global revision is the snapshot/event cursor, not a conflict gate for unrelated entity writes. All touched/read mutable dependencies require CAS. Working project source refs follow saved edits; external refs are pinned. Run admission resolves all working refs to exact revisions. Transaction aliases resolve before persistence. Technology-driven geometry, paint/erase, hierarchy, ports/maps, annotations and generic text editing are core API jobs.
8. **Testbench entity and scope.** SPICE/HDL/cocotb benches name a primary DUT and explicit nonoverlapping additional DUTs. For bench occurrence `P+[B]`, legal targets are `P+[circuit sibling]+descendants`. Deep probes remain within selected DUT closures. Stable IDs, not names or x/y positions, define scope. Placement/type/known target interface produce saved editable templates and explicit bindings. Regeneration creates new source for adoption; moves/interface/language drift mark links stale. Harness stimulus stays out of production output. I28 pins every consumed bench/DUT/model/template/interface dependency.
9. **Full installed scripting through managed publication.** Real GDSFactory and other libraries run inside the prepared worker. Project layout handles publish native geometry at explicit checkpoints using the same edit/CAS/revision boundary; arbitrary scratch mutations are not secretly durable. Earlier committed changes survive later script failure. Preserve existing worker/isolation/executable-input policy.
10. **Fast durable execution and truthful recovery.** Preserve ADR-011: one runtime, immediate dispatch after durable admission, FIFO for bursts, advisory pause/resume plus authoritative admission, no silent drop. Same request ID is idempotent; retryable pre-admission/authorization-pending outcomes can progress. Coalesce only equivalent in-flight artifact tasks. Reads/control/editor commits remain responsive during solver saturation. Survivors require explicit resume/discard; no finished replay endpoint. Cancellation requests/completion are attributed durable lifecycle evidence, superseding MCP-CONTRACT's old no-event sentence.
11. **I28 owns the project shape.** Full consumed closure includes config/references, exact target occurrence, sources/views, port/pin maps, bench bindings, geometry/layers/technology, PDK/models/decks, executable code, compiler/profile/solver versions, seeds and resolved defaults. Outputs remain exhaust until explicit adoption. No schema/UI/runtime consumer may quietly weaken this closure.

## Consequences and rollout

The contract design is frozen for parallel implementation; deployment readiness is not claimed. Changes to observable semantics begin in this bundle, receive owner/affected-consumer review, regenerate all outputs and then change providers/consumers. A breaking change versions the boundary or supplies an explicit migration. Unknown fields/modes fail instead of being silently accepted.

Refactoring proceeds through API-V1-CONTRACT, API-V1-CORE, API-V1-EDITORS, API-V1-TOOLS and API-V1-CLIENTS tickets; TESTBENCH-COMPONENT and the amended CANVAS-CST ticket hold specific authoring requirements. Completed generic ECS/legacy coalescing tickets do not prove these new typed/relational guarantees. The independent reviews' conformance matrix, real fixtures and installed-tool qualification gate implementation/deployment. Keep source modules below 3,000 lines and split cohesive responsibilities.
